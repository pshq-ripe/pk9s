# pk9s — Perl-based Kubernetes TUI

## [S1] Problem

K9s (written in Go) can be resource-heavy on large clusters. Sysadmins who already use Perl for automation need a lightweight, fast-starting alternative that:
- Avoids Bash limitations (no native data structures, process forking overhead, fragile text parsing)
- Provides a rich TUI for navigating Kubernetes resources
- Integrates with existing Perl automation workflows
- Serves as a platform for AI-assisted diagnostics and plugin ecosystem

## [S2] Solution overview

pk9s is a terminal-based Kubernetes resource browser written in Perl. It replaces K9s with a tool that:
- Starts instantly (no compilation, no binary distribution)
- Uses native Perl data structures for JSON/YAML parsing
- Provides scoped fuzzy search (e.g., `pod:plsy` filters to `polisy-deployment`)
- Manages live resources (edit, port-forward, rollout operations)
- Collects cluster context in local SQLite for AI integration
- Supports community plugins via embedded Lua interpreter

## [S3] Architecture

### Core components

```
┌─────────────────────────────────────────────────┐
│                    pk9s                         │
├─────────────┬─────────────┬─────────────────────┤
│  Backend    │    TUI      │   Plugin Engine     │
│  (Perl)     │ (Tickit/    │   (Inline::Lua)    │
│             │  Curses)    │                     │
├─────────────┼─────────────┼─────────────────────┤
│ kubectl     │ Tables      │ CRD handlers        │
│ JSON parser │ Fuzzy search│ Custom actions      │
│ Fork/pipe   │ Color codes │ Community plugins   │
│ SQLite ctx  │ Keybindings │                     │
└─────────────┴─────────────┴─────────────────────┘
         │               │               │
         ▼               ▼               ▼
    K8s API         Terminal       Local FS
    (kubectl)       (user)         (plugins/)
```

### Data flow

1. **Backend** forks `kubectl` commands, captures JSON output, decodes to Perl hashes
2. **TUI** renders resource tables with status coloring and handles keyboard navigation
3. **Fuzzy search** filters visible resources using Perl regex engine (no external fzf dependency)
4. **SQLite** stores session history, command logs, and cluster events
5. **AI sidecar** (optional) reads SQLite context and sends to local LLM for diagnostics

## [S4] Phased roadmap

### Phase 1: Backend

**Goal:** kubectl integration, JSON parsing, basic resource listing

- Fork/exec `kubectl` with proper argument handling
- Capture stdout/stderr via pipes
- Decode JSON output to Perl data structures (JSON::PP or Mojo::JSON)
- Parse resource lists into normalized internal format
- Basic error handling for cluster connection failures

**Key Perl modules:**
- `JSON::PP` (core) or `Mojo::JSON` for JSON decoding
- `IPC::Open3` for fork/pipe management
- `File::Temp` for temporary kubectl config if needed

### Phase 2: TUI

**Goal:** Interactive terminal UI with resource tables and navigation

- Render tables with `Term::Table` or `Term::ReadKey`
- Keyboard navigation (j/k or arrow keys for scrolling)
- Resource status coloring via `Term::ANSIColor` (Running=green, Error=red, etc.)
- Basic views: pods, deployments, services, nodes
- Screen refresh on data updates

**Key Perl modules:**
- `Term::Table` for formatted output
- `Term::ANSIColor` for status coloring
- `Term::ReadKey` for non-blocking keyboard input
- Optionally: `Tickit` or `Curses` for advanced TUI

### Phase 3: Scoped fuzzy search

**Goal:** fzf-style filtering with resource-type scoping

- Input field for search queries
- Scoped syntax: `pod:plsy` → filter pods matching "plsy"
- Unscoped syntax: `plsy` → search across all visible resources
- Real-time filtering as user types
- Perl regex engine for fast pattern matching

**Implementation:**
- Build regex from user input (escape special chars, partial matching)
- Filter resource list in-memory (no subprocess calls)
- Highlight matching characters in results

### Phase 4: Kubernetes operations

**Goal:** Live resource management from TUI

- **Edit:** Open resource in $EDITOR (vim), dry-run changes, apply on save
- **Port-forward:** Fork port-forward process, track by PID, kill on exit
- **Rollout:** Trigger rollout restart, monitor status
- **Delete:** Confirmation prompt before deletion
- **Logs:** Stream pod logs in split view

**Key considerations:**
- Async process management for port-forward (Parallel::ForkManager or manual fork)
- Dry-run validation before applying edits
- PID tracking for background processes

### Phase 5: AI integration & Lua plugins

**Goal:** AI-assisted diagnostics and community plugin system

- **SQLite context store:** Commands executed, pod events, error patterns
- **AI sidecar:** On keypress, send context to local LLM (Ollama/Qwen)
- **Inline::Lua:** Embed Lua interpreter for safe plugin execution
- **Plugin API:** Define custom CRD handlers, column definitions, keybindings
- **Plugin examples:** FluxCD reconcile, Velero backup status

**Plugin interface:**
```lua
-- Example: FluxCD plugin
return {
    resource = "kustomization.toolkit.fluxcd.io",
    columns = {"Name", "Ready", "Age", "Status"},
    actions = {
        r = { cmd = "flux reconcile kustomization %s", label = "Reconcile" },
        s = { cmd = "flux suspend kustomization %s", label = "Suspend" },
    }
}
```

## [S5] Design decisions

1. **Perl over Go:** Prioritizes fast startup, easy modification, and sysadmin familiarity over raw performance. No compilation step means immediate iteration.

2. **kubectl as backend:** Use kubectl as the API client rather than implementing K8s API calls directly. This ensures compatibility with kubeconfig, auth plugins, and cluster switching.

3. **SQLite for context:** Local database for session state rather than files. Enables fast queries for AI context without parsing logs.

4. **Lua for plugins:** Embedded interpreter provides sandboxed execution without Perl module dependency management. Community can distribute single .lua files.

5. **Incremental TUI:** Start with terminal tables, add advanced TUI (Tickit/Curses) only if needed. Avoids premature optimization.

## [S6] Non-goals

- Not a replacement for kubectl CLI (pk9s is a TUI wrapper, not a kubectl fork)
- Not a full cluster management tool (focused on resource browsing and quick ops)
- Not multi-cluster aware in v1 (single cluster context at a time)

## [S7] Success criteria

- Starts in <100ms on a typical machine
- Handles 1000+ pods without UI lag
- Resource operations (edit, port-forward) work reliably
- Fuzzy search filters 500 resources in <50ms
- Plugin system allows community extensions without Perl knowledge
